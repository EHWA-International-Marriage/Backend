# 이화국제결혼 Backend

이화국제결혼 홈페이지의 API 서버입니다. 상담 신청, 회원, 게시판, 사례 콘텐츠를 제공합니다.

## 기술 스택

Java 17 · Spring Boot 3 · Spring Security(JWT) · JPA + QueryDSL · MariaDB · Redis · Spring REST Docs

## SEO 전략

국제결혼을 알아보는 고객은 대부분 검색으로 업체를 찾습니다. 이 서버의 목표 중 하나는 **사례·후기·게시글처럼 계속 쌓이는 콘텐츠를 검색엔진이 잘 읽고 빠르게 색인하게 만드는 것**입니다. 화면의 메타 태그와 구조화 데이터는 프론트가 담당하고, 백엔드는 아래를 담당합니다.

| 전략 | 내용 |
|---|---|
| 의미 있는 URL | 콘텐츠마다 slug를 둡니다 (`/cases/uzbekistan-f6-visa-approval`). `?id=123` 같은 쿼리스트링 주소는 쓰지 않습니다 |
| URL 유지 | slug가 바뀌면 이전 주소를 새 주소로 301 리다이렉트해 쌓인 검색 점수를 잃지 않습니다 |
| 사이트맵 | 실제 콘텐츠 URL만 담은 사이트맵을 자동으로 만들고, 정확한 `lastmod`를 넣습니다. 프론트 정적 페이지 사이트맵과 사이트맵 인덱스로 묶습니다 |
| 빠른 색인 | 글이 등록·수정되면 IndexNow로 네이버·Bing에 바로 알리고, 프론트 빌드 훅을 호출해 정적 페이지를 다시 만듭니다 |
| 메타데이터 관리 | 글마다 `metaTitle`, `metaDescription`, `ogImage`를 저장하고 관리자가 수정할 수 있게 합니다 |
| 꾸준한 발행 | 관리자가 쉽게 글을 올리도록 에디터 이미지 업로드, 예약 발행, SEO 필드 자동 채움을 제공합니다 |
| 속도 | 이미지는 업로드 시 WebP로 변환·리사이즈하고, 목록 API는 캐시와 `Cache-Control`·`ETag`를 붙입니다 |
| 정확한 상태 코드 | 없는 콘텐츠는 반드시 404로 응답합니다 (200으로 "없음"을 보여주면 soft 404로 잡힙니다) |
| 신뢰 신호 | 상담 접수 현황을 공개 목록으로 보여주되, 이름·내용은 서버에서 마스킹하고 상세 페이지는 색인하지 않습니다 |

## 작업 규칙

### 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 배포본. 직접 push 금지 |
| `develop` | 개발 통합(기본 브랜치). 직접 push 금지 |
| `feat/…` `fix/…` `refactor/…` `test/…` `chore/…` | 작업 브랜치. develop에서 생성 |
| `hotfix/…` | 운영 긴급 수정. main에서 생성, 수정 후 develop에도 반영 |

- 이름은 영어 소문자와 `-`만 씁니다. 예: `feat/consult-api`
- 한 브랜치에는 한 가지 작업만 넣습니다.

### 커밋

`종류: 무엇을 바꿨는지` 형식으로 한 줄 요약을 씁니다.

```
feat: 상담 신청 API 추가
fix: 로그인 실패 횟수가 초기화되지 않는 문제 수정
```

### PR

1. PR 전에 `./gradlew build`(테스트 포함)가 통과하는지 확인합니다.
2. develop을 향해 PR을 엽니다. 양식이 자동으로 채워지고, 관련 이슈는 `closes #번호`로 연결합니다.
3. CI와 리뷰를 통과하면 **Squash and merge**로 합칩니다. 작업 브랜치는 자동으로 삭제됩니다.
4. 배포할 때는 `develop → main` PR을 엽니다.

### 꼭 지킬 것

- `.env`, 비밀번호, API 키, 토큰은 커밋하지 않습니다. 새 환경변수는 `.env.example`에 이름만 추가합니다.
- 고객 이름·연락처·상담 내용이 로그나 응답에 그대로 나가지 않게 합니다.
- 테이블이나 컬럼을 바꿨다면 PR 본문에 적습니다.
